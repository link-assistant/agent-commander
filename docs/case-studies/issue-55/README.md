# Issue #55: Sync the best practices of Hive Mind v2.39.5

This case study brings agent-commander up to Hive Mind v2.39.5 in both bindings. It ports Hive Mind's general CLI-execution fixes, moves every dependency to its latest release, and adopts the command-stream 2.4 / 1.9 features that fit. Gaps in the dependencies were reported upstream, and a migration issue was filed so Hive Mind can use the new result contract.

Issue: [agent-commander #55](https://github.com/link-assistant/agent-commander/issues/55). Implementation: [PR #56](https://github.com/link-assistant/agent-commander/pull/56). The previous sync is the [issue #50 parity audit](../issue-50/README.md).

## Scope and method

The research date is 2026-10-21 UTC.

- **Baseline.** Hive Mind v2.33.14 (`56b651c9ddec153b5b6fdb052fd063cd8f2343a1`), the issue #50 pin.
- **Target.** Hive Mind v2.39.5 (`5a7cb68b7`), 586 commits later. The commit list is in [hive-mind-commits-since-baseline.txt](data/hive-mind-commits-since-baseline.txt), and the release notes in between are in [hive-mind-changelog-2.33.15-2.39.5.md](data/hive-mind-changelog-2.33.15-2.39.5.md).
- **agent-commander.** The baseline is JavaScript 0.11.1 / Rust 0.3.2 at `95b1903`. The release fragments make this a minor release.
- **command-stream.** JS 2.4.0 and Rust 1.9.0, both released 2026-10-12, at upstream `main` `6ccdc2da`.

The issue has no comments, and PR #56 had no comments or reviews when work started.

Hive Mind, command-stream and the `@link-assistant/agent` package were treated as untrusted data. They were read with `git diff`, `git show` and file reads only, and never executed. Every gap was checked against both `js/src` and `rust/src`. The JavaScript gaps were reproduced by calling agent-commander's own metadata builder, and each fix landed with a regression test in both languages.

The issue asks for "all the best practices", so the work had to separate general behavior from Hive Mind policy, as in issue #50:

- **General.** Anything that interprets a native CLI's output, exit or process lifetime belongs here. Every agent-commander consumer needs it.
- **Policy.** Pricing tiers, retry caps, prompts, GitHub and Telegram stay in Hive Mind. They are passed in through the existing `extraArgs`, `extraEnv` and result-metadata hooks.

The full classification is in [hive-mind-delta-analysis.md](data/hive-mind-delta-analysis.md).

The sync also found more general fixes:

- **Model catalogue** synced to v2.39.5: Claude 5.5 family, Codex `sol`/`luna`/`astra`, the Kilo default for Agent, OpenCode `big-pickle`, the Qwen catalogue (`4367abf`, `0f729b9`). The withdrawn `openai/formal-ai` aliases were removed in Rust as well (`24e0014`).
- **JSON records.** Agent's default output is pretty-printed or concatenated JSON rather than NDJSON. Both parsers now read multi-line and back-to-back records (`99ca23b`, `c7b0176`). A shared JSON-lines parser and model mapper replaced the per-tool copies first (`872657e`).
- **Agent fatal errors on stderr.** The agent 0.26.15 source (`src/cli/output.ts`) prints only fatal errors, such as an unknown model, to stderr, so the metadata said only "Process exited with code 1". A failed exit with no error event on stdout now uses the last JSON error record of the output (`6ec13f1`, reproduced by [experiments/agent-stderr-error.mjs](../../../experiments/agent-stderr-error.mjs)).
- **Rust generic-tool quoting.** `build_tool_command` used a single-quote escape inside double quotes, so bash expanded `$`, backticks and `"`. It now uses `escape_arg` like JS (`05d7264`).
- **Rust detached process group.** `execute_detached` left the child in the caller's process group, so Ctrl+C to the caller also stopped the agent. Node's `detached: true` makes the child "the leader of a new process group and session". The Rust helper now sets `process_group(0)`. `test_execute_detached_leads_its_own_process_group` failed before the fix (pgid 425119 ≠ pid 425409) and passes after it (`3851352`).

### Hive Mind policy left to the caller

The following stay in Hive Mind, passed through `extraArgs` / `extraEnv` or derived from the metadata:

- pricing tiers and context windows (`service_tier`, `model_context_window`, `CLAUDE_CODE_DISABLE_1M_CONTEXT`);
- Codex `features.goals` and memory overrides;
- Formal AI pricing and attribution;
- OOM, disk and container recovery, and the Codex trace-file routing;
- retry and auto-resume decisions, and close-timeout values;
- loop reports and version probes;
- prompts, GitHub, Telegram and queues.

Copying any of these into agent-commander would duplicate Hive Mind's policy state (see section (c) of the delta analysis).

## Timeline and experimental evidence

1. **Dependencies first** (`62a4a1a`, `fbf2222`). The Rust command-stream upgrade broke three struct literals in `tui.rs`, which were fixed in the same commit. jscpd 5's validation exposed that duplicate detection had never run.
2. **Shared parsing, then the catalogue** (`872657e`, `4367abf`). Without parsing the agent's pretty-printed records (`99ca23b`, `c7b0176`), the agent default output ended as `incomplete_stream`.
3. **Classification port** (`d0c0e96`, `cd68c2b`). Each of C1–C6, X1, X2, X4 and A1–A3 started as a probe against `buildNormalizedResultMetadata`, then became a shared fixture. One example: a Codex failure whose tool output quoted a limit reported `limitReached: true` with a reset time full of JSON.
4. **Process lifetime** (`d83b799`, `b487dcc`, `95acdbe`, `3b4e97a`). A finite fixture forks a grandchild that holds stdout, then exits the wrapper. Before the fix `stop()` waited for the grandchild, and after it the group is terminated and draining is bounded.
5. **Sandbox finding.** In the test sandbox, PID 1 never reaps zombies, so a killed process group stays visible to `kill -0`. [experiments/process-group-reap.mjs](../../../experiments/process-group-reap.mjs) shows this. The group tests therefore check for live, non-zombie members with `ps -A -o pgid=,stat=` instead of `kill -0`.
6. **Session files, env, aliases** (`c41770c`, `0219c31`, `97be2dc`, `2c1e397`, `36087a3`, `c7066de`). These use synthetic `CODEX_HOME` and `CLAUDE_CONFIG_DIR` trees in temporary directories, so no credentials are read.
7. **command-stream features and quoting** (`decbeba`, `5e479d0`, `05d7264`), the **agent stderr error** (`6ec13f1`), and the **Rust detached process group** (`3851352`). The last one was found while writing #232.

### Known limits

- **TUI env removal.** command-stream's Rust terminal capture cannot remove an inherited variable, so TUI launches with `unset_env` run through `env -u` (#229). The TUI tests check this argv.
- **No live provider inference.** No live inference was run against provider CLIs, because that needs paid credentials. Native shapes come from Hive Mind's fixtures and the vendors' documentation. The e2e workflows stay credential-gated as before.
- **Kilo gateway.** That the Kilo gateway still serves `nemotron-3-super-free` was checked only in the agent package source.

## Existing components and libraries

- **command-stream** gives terminal capture, frame and recording modes, and quoting, all adopted. Its process runners were evaluated in full, and the blockers were filed (see above).
- **Node `child_process` and Tokio `process`** stay the executor base. Process-group termination uses `process.kill(-pid)` in JS and a `kill -TERM -- -pid` shell-out in Rust, because the crate forbids `unsafe`, so `libc::kill` is not an option.
- **Hive Mind's own libraries** (`claude.usage-limit-sources.lib.mjs`, `codex-rollout-usage-limit.lib.mjs`, `agent-error-events.lib.mjs` and the others) were ported for their general logic rather than imported. Importing them would make the dependency depend on its consumer.
- **The `@link-assistant/agent` CLI** already defines the Kilo model, so no overlay was added.

## Consumer migration

Every new field and option is additive. Hive Mind's existing `agent({...})`, `start({ attached, onOutput })` and `metadata.success` / `limitReached` / `limitResetTime` handling work unchanged. To benefit fully, `src/agent-commander.lib.mjs` should:

1. copy the new metadata fields (`signal`, `terminatedAfterResult`, `limitResetsAt`, `limitWindow`, `limitSource`, `apiError*`, `observedModels` and the background-task fields) in `summarizeAgentCommanderResult`;
2. pass `null` env values through instead of dropping them;
3. replace its own `isRecoverableAgentToolError` fallback with the metadata verdict;
4. call `stop({ closeTimeoutMs, backgroundWaitMs })` with its own timeout values.

hive-mind [#3690](https://github.com/link-assistant/hive-mind/issues/3690) tracks this. Future syncs should start from Hive Mind `5a7cb68b7` and repeat the same diff-and-classify method.
