# Issue #50: Hive Mind dependency parity

This audit synchronizes the general CLI execution contracts that Hive Mind needs from agent-commander across JavaScript and Rust. It adds deterministic coverage for all six tools and fixes model drift, native command flags, usage accounting, session outcomes, process draining, cancellation and quoting. Hive Mind's repository automation continues to compose these primitives.

Issue: [agent-commander #50](https://github.com/link-assistant/agent-commander/issues/50). Implementation and review: [PR #51](https://github.com/link-assistant/agent-commander/pull/51).

## Scope and method

Research date: 2026-10-07 UTC. The baseline is agent-commander `c03d6f87f6bb37b1e827c6ec2b6c9cd5f6a49f49` (JavaScript 0.10.1, Rust 0.2.7); the prepared branch initially adds only task bookkeeping at `71cef7a837f92c834883ad3f65ad48afa20fd9d6`. Hive Mind is pinned to `56b651c9ddec153b5b6fdb052fd063cd8f2343a1` for a reproducible comparison.

“General features” means the reusable boundary between an orchestrator and installed native CLIs: invocation, prompt transport, model selection, native configuration, permissions, output, sessions, usage and process lifetime. Hive Mind's own adapter already uses this boundary. Its GitHub, Telegram, queue, credential installation and recovery policies remain consumer responsibilities. Copying those into this dependency would create an application dependency cycle and duplicate their policy state.

The investigation read the entire issue and comments (none), the existing PR discussion/reviews (none at start), local contributing instructions, the upstream adapter, catalogue, relevant parsers and recent merged work. Raw issue data, upstream source snapshots, search results and PR bodies are in [data](data/). [The evidence index](data/evidence-index.json) records hashes and online sources. The downloaded screenshot in Hive Mind PR #2291 was checked as a valid PNG and inspected; it shows the caller rejecting a newly discovered model before invoking its CLI. Its original link is retained in the raw PR body. This PR changes no visual UI.

## Root causes and fixes

### Catalogue drift and incompatible native flags

The two bindings embedded separate, older model maps. Hive Mind moved to a centralized catalogue with live exact IDs; the dependency continued to publish older aliases/defaults. The replay compares all 206 entries against the pinned catalogue. JavaScript now shares one generated catalogue; Rust maps are generated from the same data. Legacy keys absent from the source remain accepted. Unknown exact IDs continue through unchanged, leaving validation and capability discovery to the caller.

Claude's old inline `--prompt` path did not match native print invocation, and JSON commands did not always request print/verbose output. Builders now use native `-p` and add `--verbose` when stream JSON is selected. Resuming Gemini was dropped by the common builder; OpenCode used a different backend's `--resume` flag; Agent advertised no resume despite Hive Mind using `--resume ... --no-fork`. All six common resume paths now map to the native contract.

### Snapshots, final totals and cache accounting

A single “sum every usage object” strategy double-counted Claude/Qwen final totals and repeated snapshots. OpenCode's native usage lives in `part.tokens`, while Gemini often reports `result.stats.models[*].tokens`. Rust's controller dropped Qwen/Gemini usage entirely. Codex's inclusive input concealed cached reads, making its output incompatible with Hive Mind's fresh-input accounting.

The parsers now select final totals when present, otherwise deduplicate identified snapshots; Agent/OpenCode sum native steps. Codex reports fresh input and cache reads separately, with nested cache/reasoning vocabulary retained. This is a deliberate documented semantic change. The simple fixture `input=100, cached=80` changes from input 100 to input 20 plus cache reads 80. Reasoning may already belong to native output totals and must not be added again for billing.

### Process status and session status

Exit code zero does not prove an agent completed its turn. An interrupted JSON stream previously passed even after init/turn-started events; signal exits with no numeric status were also treated as zero in JavaScript. The new state tracker follows the last native turn. Direct JSON controllers also reject empty or unrecognized output without completion evidence. Plain/generic command execution retains exit semantics when no native lifecycle is observed.

A terminal success supersedes earlier recoverable transport errors and quoted usage-limit text; errors emitted after it still fail. Claude events with `parent_tool_use_id` are diagnostics for a subagent and cannot replace the parent's verdict, summary or totals. Those raw events remain available, and actual native Task/Agent/collaboration records are exposed separately. This follows the main-thread boundary fixed upstream in PR #2302; it does not automatically implement Hive Mind's background-task continuation policy.

### Framing, deadlocks and shell transport

Combining stderr with stdout before JSON parsing let a diagnostic JSON line change session identity, usage or success. Both bindings now parse stdout independently. Raw output still includes diagnostics for callers' investigations. JavaScript uses incremental UTF-8 decoding so chunk boundaries cannot corrupt multibyte characters.

Rust previously waited/read in an order that could deadlock when stderr filled its pipe before stdout closed. Reader tasks now start immediately and drain both pipes concurrently, with attached writes and byte-preserving collection. The finite regression emits 128 KiB to stderr then `done` to stdout; a five-second test bound makes the old deadlock reproducible without exhausting memory. Cancelling signals the direct Unix process group, waits for readers and cleans up prompts. Unregistering a Rust signal handler no longer invokes its cleanup callback.

The previous safe-word heuristic left shell metacharacters unquoted when no spaces were present. A narrow safe-character allowlist and proper quoting of the working directory preserve arguments such as `one;two'&three|four` and paths with spaces. Prompt files continue to keep large user text out of command strings.

## Primary-source research

- [OpenAI non-interactive Codex documentation](https://developers.openai.com/codex/noninteractive) describes exec/resume, JSONL lifecycle and separate cached-input usage. Its turn events provide a native completion boundary. Model capability selection remains the consumer's job.
- [Claude Code headless documentation](https://code.claude.com/docs/en/headless) describes print mode, stream JSON with verbose output, session continuation and final result fields. This supports the native flags and result-total handling.
- [Gemini headless documentation](https://geminicli.com/docs/cli/headless/) describes text, single JSON and streaming JSON outputs, result statistics, error records and process status. Protocol success and process exit are separate evidence.
- [Qwen headless documentation](https://qwenlm.github.io/qwen-code-docs/en/users/features/headless/) describes stdin prompts, continue/resume and JSON formats. Its JSON input support is described as under construction; the dependency's approval relay remains disabled for Qwen.
- [OpenCode CLI documentation](https://opencode.ai/v2/docs/cli/commands/) describes noninteractive `run`, JSON output and continuation. Its flag list is version-specific; the pinned Hive Mind native path supplies the `--session` mapping used here.
- [Node child process documentation](https://nodejs.org/api/child_process.html) explains that close follows stdio completion, signals can produce a null exit code, and killing a shell does not necessarily kill its children. These facts motivate nonzero signal status and Unix group cancellation.
- [Tokio process documentation](https://docs.rs/tokio/latest/tokio/process/) covers asynchronous process management and `kill_on_drop`. Concurrent readers avoid pipe backpressure while waiting for the child.

## Existing components and alternatives

| Component                                                          | Fit and decision                                                                                                                                                      |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Existing native tool builders, NDJSON streams and permission relay | Reuse them and add native-schema coverage. A second parser/permission framework would duplicate public contracts                                                      |
| Node `child_process`                                               | Keep the existing direct JS executor, add encoding and group cancellation; no new process dependency required                                                         |
| Tokio process/tasks/I/O                                            | Reuse the existing Rust dependency for concurrent readers and cancellation; preserve `unsafe_code = forbid`                                                           |
| Existing `command-stream` dependency                               | Retain for interactive TUI capture/normalized events; full default suites verify this feature remains intact                                                          |
| Vendor SDKs / agent server APIs / ACP                              | Useful for an alternative transport, but introduce per-provider APIs, auth and version coupling; they do not replace Hive Mind's installed CLI workflows              |
| A copied full Hive Mind runner                                     | Would import application state, routers, queues and GitHub logic into the dependency; compose the existing adapter with its own policies instead                      |
| Raw native argv/env escape hatch                                   | Best fit for fast-moving reasoning, memory, MCP, compaction/subagent model and background-ceiling options; callers resolve semantics using installed CLI capabilities |

No additional runtime dependency is introduced. Reproduction and catalogue regeneration scripts are retained in [experiments](../../../experiments/).

## Consumer migration and continuing synchronization

1. Upgrade the dependency after the included JavaScript Changeset and Rust changelog fragment produce their minor releases. Exact model IDs and raw overrides remain supported; account for the documented Codex fresh-input semantic change and new Rust usage fields.
2. Keep the existing controller/result adapter. Resolve live IDs, capabilities, prices and router settings in Hive Mind, then pass them through the dependency's common options and native overrides.
3. Select `attached: false` when Hive Mind's `onOutput` callback writes chunks itself. Its current adapter combines attached output and manual echoing, which duplicates logging; this repository supplies an example of single-output ownership without altering callback semantics.
4. Use `metadata.success`, session/error fields and raw output to apply bounded retries. Preserve Hive Mind's background-task ceiling detection, OOM recovery and auto-resume policy; configure native environment via `extraEnv`.
5. For isolated jobs, run the direct controller inside Hive Mind's installed/authenticated image or Screen task and collect its native result there. Existing library Screen/Docker stop results describe wrapper commands, not the stopped agent's semantic completion. The simple default Docker image does not provision six authenticated tools.
6. When native CLIs change, run `node experiments/collect-hive-mind-parity.mjs CHECKOUT`, `python3 experiments/sync-model-catalog.py`, and `python3 experiments/create-parity-fixtures.py`; format, review changes and run both suites. Pinned IDs remain accepted, and fixture equality detects cross-language drift.

The audit is complete for the general dependency boundary. Further vendor-specific policy changes can use these existing extension points, while native protocol changes should add a failing shared fixture before updating either binding.
